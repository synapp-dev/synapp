# CONTEXT.md format (domain glossary)

Project-wide domain vocabulary lives in **`CONTEXT.md` at the repository root** (create it if missing).

## When to add or change a term

- You name a deepened module or seam after a **concept** that callers will use — that name should exist in `CONTEXT.md`.
- You sharpen a fuzzy term during a grilling or design conversation — update `CONTEXT.md` in the same session.

## Entry shape

Keep entries short and decision-oriented:

- **Term** — one line definition the whole team can reuse.
- Optional: **Contrasts with** / **Not** — disambiguate from nearby concepts.
- Optional: **Owns** — which behaviours or data the concept covers (helps pick seam names).

Do not paste implementation details; glossary only.
